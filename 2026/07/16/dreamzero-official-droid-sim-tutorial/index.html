DreamZero 官方 DROID 仿真：从空机器到生成视频

这是一条单一路线教程：使用官方 DreamZero-DROID 14B 权重启动策略服务，再用官方引用的 DROID Isaac Lab 环境运行仿真。
本文不包含训练、LIBERO、真机部署或 GB200 TensorRT 优化。
核对日期：2026-07-13。

1. 完成后你会得到什么

完成本文后，两台机器的关系如下：

仿真机 B（Isaac Lab）                       模型机 A（DreamZero）
┌──────────────────────┐                 ┌─────────────────────────┐
│ DROID 仿真环境        │  WebSocket      │ DreamZero-DROID 14B      │
│ 3 路相机 + 机器人状态  │ ──────────────> │ 2×H100 分布式推理         │
│                      │  8 维动作块       │                         │
│ 保存实际 rollout 视频 │ <────────────── │ 保存模型预测的未来视频     │
└──────────────────────┘   TCP 5000      └─────────────────────────┘

最终会生成两类视频：

视频 在哪台机器 保存位置 内容
仿真实际 rollout 仿真机 B /data/dreamzero/src/dreamzero/runs/YYYY-MM-DD/HH-MM-SS/episode_0.mp4 仿真执行过程，画面为右外部相机、腕部相机、左外部相机横向拼接，15 FPS
DreamZero 预测视频 模型机 A /data/dreamzero/checkpoints/real_world_eval_gen_YYYYMMDD_0/DreamZero-DROID/*.mp4 模型内部生成的未来视频预测，5 FPS；不是仿真实际运动轨迹

仿真视频在一个 episode 完成后写入。模型预测视频通常在 episode reset 或客户端断开时写入。

2. 本教程使用的机器

模型机 A

项目 配置
操作系统 Ubuntu 22.04 x86_64
GPU 2×NVIDIA H100 80GB，位于同一节点
CPU 32 核以上
内存 256GB 以上
磁盘 200GB 以上可用 NVMe
网络 与仿真机处于同一内网
本文示例 IP 10.0.0.10

DreamZero README 明确要求至少 2 张 GPU，并声明测试过 H100 与 GB200。本文使用 H100 的 PyTorch 路线。

仿真机 B

项目 配置
操作系统 Ubuntu 22.04 x86_64
GPU 1×NVIDIA L40S 48GB，或 RTX 6000 Ada 48GB
CPU 16 核以上
内存 64GB 以上
磁盘 120GB 以上可用 SSD
网络 能访问模型机 10.0.0.10:5000
本文示例 IP 10.0.0.20

sim-evals 没有公开最低 GPU 规格。这里选用 48GB RTX 级 GPU，是为了给 Isaac Sim、相机渲染和缓存留出余量；这属于保守工程配置，不是官方最低要求。

网络要求

模型服务会监听 0.0.0.0:5000。只允许仿真机访问该端口，不要把未认证的 WebSocket 服务直接暴露到公网。

本文中的两个示例 IP 必须替换成你机器的真实内网 IP。

3. 固定代码版本

本文按以下版本编写：

仓库 Commit
https://github.com/dreamzero0/dreamzero ab790c198fbce33503358efbbd4187ce9a89adf3
https://github.com/arhanjain/sim-evals 3a6b0e8177f696947f49c082728f10ef5133ede1

两台机器都需要 DreamZero 源码，但只有模型机需要下载 14B 权重。

4. 模型机 A：安装 DreamZero

以下命令全部在 模型机 A 的终端 A1 中执行。

4.1 检查 GPU 和磁盘

nvidia-smi
nvidia-smi -L
nvidia-smi topo -m
df -h /data

你应该看到两张 H100。nvidia-smi topo -m 应显示两张卡位于同一节点，并有高速互联。

4.2 安装系统工具

sudo apt-get update
sudo apt-get install -y \
  git git-lfs curl wget build-essential ninja-build \
  ffmpeg libgl1 libglib2.0-0 netcat-openbsd

git lfs install

4.3 安装 Miniconda

如果模型机已经有可用的 Conda，可跳过本节。

cd /tmp
wget https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh
bash Miniconda3-latest-Linux-x86_64.sh -b -p "$HOME/miniconda3"
source "$HOME/miniconda3/etc/profile.d/conda.sh"
conda init bash

重新打开终端后确认：

conda --version

4.4 克隆 DreamZero

sudo mkdir -p /data/dreamzero/src /data/dreamzero/checkpoints
sudo chown -R "$USER":"$USER" /data/dreamzero

cd /data/dreamzero/src
git clone https://github.com/dreamzero0/dreamzero.git
cd dreamzero
git checkout ab790c198fbce33503358efbbd4187ce9a89adf3

git rev-parse HEAD
git status --short

预期：

  • git rev-parse HEAD 输出完整 commit ab790c...。
  • git status --short 没有输出。

4.5 创建 Python 环境

source "$HOME/miniconda3/etc/profile.d/conda.sh"
conda create -n dreamzero python=3.11 -y
conda activate dreamzero

python -m pip install -U pip setuptools wheel
cd /data/dreamzero/src/dreamzero
pip install -e . --extra-index-url https://download.pytorch.org/whl/cu129
MAX_JOBS=8 pip install --no-build-isolation flash-attn

H100 基线不需要安装 README 中标注为 GB200 专用的 Transformer Engine 和 TensorRT NVFP4 组件。

4.6 验证 Python、Torch 和 GPU

python - <<'PY'
import torch
import flash_attn

print("torch =", torch.__version__)
print("torch CUDA =", torch.version.cuda)
print("GPU count =", torch.cuda.device_count())
print("BF16 supported =", torch.cuda.is_bf16_supported())
for i in range(torch.cuda.device_count()):
    print(i, torch.cuda.get_device_name(i))
PY

至少应满足：

GPU count = 2
BF16 supported = True

如果这里失败，不要继续下载权重。先修复驱动、Torch CUDA wheel 或 FlashAttention 编译问题。

5. 模型机 A：下载 DreamZero-DROID 权重

继续在 模型机 A 的终端 A1 执行。

5.1 下载不含 TensorRT 的 PyTorch 权重

conda activate dreamzero
pip install -U "huggingface_hub[cli]"

hf download GEAR-Dreams/DreamZero-DROID \
  --repo-type model \
  --local-dir /data/dreamzero/checkpoints/DreamZero-DROID \
  --exclude "tensorrt/**"

如果 Hugging Face 要求令牌：

export HF_TOKEN='你的 Hugging Face Token'

不要把 token 写入文档、Shell 历史共享文件或 Git 仓库。

5.2 验证权重完整性

cd /data/dreamzero/checkpoints/DreamZero-DROID

test -f config.json && echo "config.json OK"
test -f model.safetensors.index.json && echo "index OK"
echo "shard count: $(find . -maxdepth 1 -name 'model-*.safetensors' | wc -l)"
du -sh .

预期：

config.json OK
index OK
shard count: 10

10 个 BF16 模型分片合计约 46GB。不要用 Hugging Face 页面显示的历史 usedStorage 代替本地实际大小。

6. 仿真机 B：安装 DROID Isaac Lab 环境

以下命令全部在 仿真机 B 的终端 B1 执行。

DreamZero 模型环境使用 PyTorch 2.8/CUDA 12.9，而 sim-evals 固定 Isaac Lab 2.2.0，并将 Torch 指向 CUDA 11.8。两套环境不要混装。

6.1 检查 GPU 和磁盘

nvidia-smi
nvidia-smi -L
df -h /data

6.2 安装系统工具

sudo apt-get update
sudo apt-get install -y \
  git git-lfs curl build-essential ffmpeg netcat-openbsd \
  libgl1 libegl1 libglib2.0-0 libx11-6 libxrandr2 \
  libxinerama1 libxcursor1 libxi6 libsm6

git lfs install

6.3 克隆 DreamZero

仿真机需要 DreamZero 中的适配脚本，但不需要下载模型权重。

sudo mkdir -p /data/dreamzero/src
sudo chown -R "$USER":"$USER" /data/dreamzero

cd /data/dreamzero/src
git clone https://github.com/dreamzero0/dreamzero.git
cd dreamzero
git checkout ab790c198fbce33503358efbbd4187ce9a89adf3

6.4 克隆并安装 sim-evals

cd /data/dreamzero/src
git clone https://github.com/arhanjain/sim-evals.git
cd sim-evals
git checkout 3a6b0e8177f696947f49c082728f10ef5133ede1

curl -LsSf https://astral.sh/uv/install.sh | sh
source "$HOME/.local/bin/env" 2>/dev/null || true
export PATH="$HOME/.local/bin:$PATH"

uv sync
source .venv/bin/activate

验证环境：

which python
python --version
python -c "import torch; print(torch.__version__, torch.version.cuda)"
python -c "import sim_evals; print(sim_evals.__file__)"

Python 应为 3.11。sim-evals 的依赖配置会安装 isaaclab[all,isaacsim]==2.2.0。

6.5 下载 DROID 仿真资产

cd /data/dreamzero/src/sim-evals
source .venv/bin/activate

uvx hf download owhan/DROID-sim-environments \
  --repo-type dataset \
  --local-dir assets

du -sh assets

7. 启动顺序

这一节必须按顺序执行。先启动模型服务，再启动仿真。

7.1 模型机 A：启动 DreamZero 服务

在 模型机 A 的终端 A1 执行：

source "$HOME/miniconda3/etc/profile.d/conda.sh"
conda activate dreamzero
cd /data/dreamzero/src/dreamzero

export CUDA_VISIBLE_DEVICES=0,1

python -m torch.distributed.run \
  --standalone \
  --nproc_per_node=2 \
  socket_test_optimized_AR.py \
  --port 5000 \
  --enable-dit-cache \
  --model-path /data/dreamzero/checkpoints/DreamZero-DROID

这条命令会一直占用终端，属于正常现象。不要按 Ctrl+C。

首次加载和前几次推理可能需要数分钟。服务就绪时，应看到类似信息：

Videos will be saved to: /data/dreamzero/checkpoints/real_world_eval_gen_YYYYMMDD_0/DreamZero-DROID
Using roboarena policy server interface
server listening on 0.0.0.0:5000

如果模型尚未完成加载，仿真机不要开始评测。

7.2 模型机 A：检查端口和显存

另开 模型机 A 的终端 A2：

ss -lntp | grep 5000
nvidia-smi

预期端口 5000 正在监听，两张 H100 都有模型显存占用。

7.3 仿真机 B：检查网络

在 仿真机 B 的终端 B1 执行。把 10.0.0.10 替换成真实模型机 IP。

export MODEL_IP=10.0.0.10
export MODEL_PORT=5000

ping -c 2 "$MODEL_IP"
nc -vz "$MODEL_IP" "$MODEL_PORT"

预期：

Connection to 10.0.0.10 5000 port [tcp/*] succeeded!

如果失败，检查模型服务是否已就绪，以及模型机防火墙或云安全组是否允许仿真机 IP 访问 TCP 5000。

8. 仿真机 B：先跑 Scene 1

仍在 仿真机 B 的终端 B1 执行：

cd /data/dreamzero/src/sim-evals
source .venv/bin/activate

cd /data/dreamzero/src/dreamzero
export CUDA_VISIBLE_DEVICES=0
export MODEL_IP=10.0.0.10
export MODEL_PORT=5000

python eval_utils/run_sim_eval.py \
  --episodes 1 \
  --scene 1 \
  --host "$MODEL_IP" \
  --port "$MODEL_PORT"

脚本会自动启动 Isaac Sim、加载场景并连接 DreamZero 服务。仿真侧不需要再启动另一个后台服务。

Scene 1 的语言指令已经写在脚本中：

put the cube in the bowl

用户不需要另行输入 prompt；--scene 1 会自动选择该指令和对应场景。

第一次启动 Isaac Sim 可能需要较长时间初始化扩展、shader cache 和资产。模型机 A1 应出现客户端连接和推理日志。

8.1 Scene 1 完成后找视频

仿真脚本结束后，在仿真机执行：

cd /data/dreamzero/src/dreamzero
find runs -type f -name 'episode_*.mp4' -printf '%TY-%Tm-%Td %TH:%TM %p\n' | sort

最新文件类似：

runs/2026-07-13/15-30-42/episode_0.mp4

它是 15 FPS 的仿真实际 rollout，画面从左到右依次为：

右外部相机 | 腕部相机 | 左外部相机

在有桌面环境的机器上可播放：

ffplay runs/2026-07-13/15-30-42/episode_0.mp4

远程服务器没有桌面时，将 MP4 下载到本地查看。

8.2 在模型机查预测视频

在 模型机 A 的终端 A2 执行：

find /data/dreamzero/checkpoints \
  -path '*/real_world_eval_gen_*/*/*.mp4' \
  -printf '%TY-%Tm-%Td %TH:%TM %p\n' | sort

文件类似：

/data/dreamzero/checkpoints/
└── real_world_eval_gen_20260713_0/
    └── DreamZero-DROID/
        └── 000000_07_13_15_31_09_n4.mp4

这是模型预测的未来视频，帧率为 5 FPS。它用于观察 DreamZero 的世界预测，不应当作实际仿真成功录像。

同一目录下的 inputs/ 保存发送给模型的观测帧，可用于排查相机顺序和输入内容。

9. 依次运行 Scene 2 和 Scene 3

保持模型机 A1 的 DreamZero 服务不停止。

9.1 Scene 2

在仿真机 B1 执行：

cd /data/dreamzero/src/sim-evals
source .venv/bin/activate
cd /data/dreamzero/src/dreamzero

export CUDA_VISIBLE_DEVICES=0
export MODEL_IP=10.0.0.10
export MODEL_PORT=5000

python eval_utils/run_sim_eval.py \
  --episodes 1 \
  --scene 2 \
  --host "$MODEL_IP" \
  --port "$MODEL_PORT"

对应指令：

pick up the can and put it in the mug

9.2 Scene 3

python eval_utils/run_sim_eval.py \
  --episodes 1 \
  --scene 3 \
  --host "$MODEL_IP" \
  --port "$MODEL_PORT"

对应指令：

put the banana in the bin

每次运行都会创建新的时间戳目录。三个场景完成后检查：

find /data/dreamzero/src/dreamzero/runs \
  -type f -name 'episode_0.mp4' \
  -printf '%TY-%Tm-%Td %TH:%TM %p\n' | sort

应该至少看到三个新 MP4。

10. 如何判断“跑通”和“任务成功”

跑通

满足以下条件可认定技术链路跑通：

  • 模型服务成功加载两张 H100，并监听 5000 端口。
  • 仿真机可以建立 WebSocket 连接。
  • 模型返回二维动作块，最后一维为 8，即 7 个关节位置加 1 个夹爪动作。
  • Isaac Lab 能持续执行动作直到 episode 结束。
  • 仿真机生成可播放的 episode_0.mp4。
  • 模型机生成预测视频或至少保存输入观测。

任务成功

进程正常退出只表示链路跑通，不代表机器人完成任务。当前 run_sim_eval.py 没有输出一个标准化的三场景成功率汇总，因此需要查看 rollout 视频，并记录：

场景 成功条件
Scene 1 方块最终进入碗中
Scene 2 罐子最终进入杯子中
Scene 3 香蕉最终进入箱子中

建议为每个场景至少运行 10 个 episode，人工或另外编写统计脚本计算成功率。本文的一条龙验收只要求每个场景先完成 1 个 episode。

11. 停止服务

所有场景运行完成后，回到 模型机 A 的终端 A1，按：

Ctrl+C

随后确认端口已释放：

ss -lntp | grep 5000

无输出表示服务已停止。

12. 常见故障

现象 优先检查
模型机没有监听 5000 A1 是否仍在加载模型；两个 worker 是否都正常；是否出现 CUDA OOM
仿真机 nc 连接失败 MODEL_IP 是否正确；模型机防火墙/安全组；服务是否监听 0.0.0.0:5000
GPU count 小于 2 CUDA_VISIBLE_DEVICES、容器 GPU 映射、调度系统实际分配的 GPU 数
flash-attn 编译失败 Torch 是否先安装；nvcc 和编译器是否可见；尝试 MAX_JOBS=2 重新安装
Isaac Sim 启动失败 仿真机是否使用 RTX GPU；驱动是否正常；系统 OpenGL/EGL 库是否齐全
import sim_evals 失败 是否激活 /data/dreamzero/src/sim-evals/.venv；是否在该仓库执行过 uv sync
动作维度断言失败 是否使用 DreamZero-DROID checkpoint；embodiment 是否为 DROID；不要通过数组裁切掩盖错误
仿真机没有 MP4 episode 是否真正结束；当前工作目录是否为 DreamZero 根目录；检查磁盘空间
模型机没有预测 MP4 等待 episode reset 或客户端断开；检查 A1 的 Saved video on reset to: 日志；查看 inputs/ 是否已生成

13. 最终检查清单

  • 模型机有 2×H100 80GB，仿真机有 1×L40S/RTX 6000 Ada 48GB。
  • 两台机器使用同一内网，但只向仿真机开放 TCP 5000。
  • 两台机器的 DreamZero commit 均为 ab790c1。
  • sim-evals commit 为 3a6b0e8。
  • 模型机存在 10 个 model-*.safetensors 分片。
  • 模型机 A1 的服务保持运行，A2 能看到 5000 端口和双卡显存占用。
  • 仿真机可以通过 nc -vz MODEL_IP 5000 连接模型机。
  • Scene 1、2、3 各生成至少一个 episode_0.mp4。
  • 仿真录像和模型预测视频已分开保存和解释。
  • 已查看视频并单独记录“链路跑通”与“任务是否成功”。
